Forudsætninger og prisregler
  • Nye priser beregnes som jeres faktiske omkostning ganget med forholdet mellem listeprisen i målregionen og listeprisen i den region, ressourcen kører i i dag. Jeres rabatprocent følger dermed med. Listepriser hentes i USD fra Azure Retail Prices API, men forholdstallet er uafhængigt af valuta.
  • Meters matches på tværs af regioner på produkt, SKU og meternavn. Findes et match ikke, er tjenesten eller størrelsen ikke tilgængelig i regionen, og omkostningen medtages uændret og markeres.
  • Globale meters og trafikzoner (f.eks. Zone 1) er ens på tværs af regioner og medtages uændret.
  • Kun linjer med gebyrtypen Usage indgår. Køb, refusioner og ubrugte reservationer vises separat. Brug en amortiseret eksport, hvis I har reservationer eller savings plans; ellers står reservationsforbrug til 0 kr.
  • Prisstigningerne gælder fra 1. februar 2027. Regionale stigninger gælder virtuelle maskiner og storage:
  • Ældre v1- og v2-serier stiger ca. 25 % i alle regioner i stedet for den regionale stigning: Bv1, D, Ds, F, Fs, G, Gs, Ls, NP, HC, Av2, Amv2, Dv2, Dsv2, Fsv2 og Lsv2.
  • Undtaget fra den regionale stigning: v7-VM'er samt Queues, Tables, General Block Blob, Standard Page Blob, Transaction Optimized og Azure Container Storage.
  • Savings plans beskytter ikke mod stigningen og behandles som pay-as-you-go. Tiered meters beregnes ud fra laveste betalte trin.
  • Prisreglerne ligger i rules.js, så de kan rettes, hvis Microsoft justerer listen.
